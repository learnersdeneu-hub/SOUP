# v2.8 Engineering Hardening

This patch is intentionally narrow: it hardens the frozen v2.7 deployment candidate rather than rebuilding SOUP.

## Changes

- Added Zod and centralized JSON request parsing.
- Added shared authenticated API user/profile guards.
- Migrated core application, journey and conversation mutations to typed schemas.
- Added authenticated ownership enforcement to premium payment verification.
- Added Vitest with unit/security tests.
- Added structural API auth-route auditing and client-secret boundary tests.
- Added an `any` regression budget; reduced source `any` tokens from the observed hardening baseline to 118 and prevented growth while remaining sites are converted safely.
- Added defense-in-depth Supabase/Postgres RLS policies for core user-owned tables used through direct Supabase access.
- Kept Prisma as the trusted server data layer; server-side ownership/role checks remain mandatory.
- Archived historical release/debug reports under `docs/history/` and replaced root clutter with current architecture/security/testing/deployment documentation.
- Added a single `verify:deploy` gate combining automated tests, auth audit, type-safety budget, product checks, Prisma validation, TypeScript and Next production build.

## Required local proof

The artifact environment cannot complete dependency installation, so `npm test`, `npm run typecheck` and `npm run build` must be run on the configured local machine before deployment. Source-only repository, migration, auth, type-budget and deep SOUP invariant checks pass in the artifact environment.
